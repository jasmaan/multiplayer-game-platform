# Game Ends, Store Results, Show Result Screen

## About

This refined sequence matches the current code path after a terminal move:

- `GameSessionManager.submitMove(...)` handles the terminal move: validation, apply, end detection, winner lookup, session status updates, and final accepted `MoveSubmissionResult`.
- `PlatformCore.submitMove(...)` publishes the final `GameStateUpdate`, and `PlatformCore.handleGameStateUpdate(...)` stores results through `Leaderboard`, saves profiles through `UserRepository`, sends game-over alerts, and moves players to `VIEWING_RESULTS`.
- In local play, the submitting controller shows the result overlay from the returned `GameStateUpdate`.
- In network play, `MessageRouter.handleSubmitMove(...)` uses the same `PlatformCore.submitMove(...)` path, then broadcasts `GAME_STATE` separately to session players.
- Room cleanup, rematch flow, and leaving the result screen happen later from controller actions; they are not automatic parts of this game-over event path.

## PlantUML Editor Code

```uml
@startuml
title Sequence - Game Over -> Store Results -> Show Result Screen
actor "Current Player" as P1
actor "Opponent" as P2

participant "GUI\n(Game Page - P1)" as GUI_P1
participant "PlatformCore" as Core
participant "GameSessionManager" as GSM
participant "GameSession" as Session
participant "GameEngine" as Engine
participant "EventBus" as Bus
participant "Leaderboard" as LB
participant "Database\n(stub)" as DB
participant "UserRepository" as Repo
participant "NotificationService" as Notify

== Final Move Submitted ==

P1 -> GUI_P1 : submit terminal move
GUI_P1 -> Core : submitMove(sessionId, P1, move)
Core -> GSM : submitMove(sessionId, P1, move)

GSM -> Engine : validateMove(state, move)
Engine --> GSM : valid
GSM -> Engine : applyMove(state, move)
Engine --> GSM : newBoard

== End Condition Detected ==

GSM -> Engine : evaluateEnd(newBoard)
Engine --> GSM : gameOver = true
GSM -> Engine : getWinner(newBoard)
Engine --> GSM : winnerId / null

== Update Session Status ==

GSM -> GSM : set game state status = GAME_OVER
GSM -> Session : setStatus(GAME_OVER)
GSM -> Session : setEndTime(now)
GSM -> GSM : build GameStateUpdate(\nstatus=GAME_OVER,\ngameOver=true,\nwinnerId)
GSM --> Core : MoveSubmissionResult.accepted(update)

== Publish Final Game State ==

Core -> Bus : publish(GameStateUpdate)
Bus --> Core : handle(GameStateUpdate)

== Record Results & Update Stats ==

Core -> GSM : getSession(sessionId)
GSM --> Core : session
Core -> LB : logGameResult(sessionId, winnerId,\nloserId, isDraw)
LB -> DB : storeData(result + player history)

loop for each session player
  Core -> LB : updatePlayerRanking(playerId, gameType, outcome)
  LB -> DB : retrieve/store ranking data
  Core -> LB : getPlayerMmr(playerId, gameType)
  LB -> DB : retrieve ranking
  Core -> LB : getOverallTier(playerId)
  LB -> DB : retrieve tier data
  Core -> Repo : save(updated profile)
end

== Notify Players ==

Core -> Notify : createGameOverAlert(P1,\nsessionId, result, context)
Core -> Notify : createGameOverAlert(P2,\nsessionId, result, context)
Core -> Core : setPlayerContext(P1,\nVIEWING_RESULTS)
Core -> Core : setPlayerContext(P2,\nVIEWING_RESULTS)

== Show Result Screen ==

Core --> GUI_P1 : return accepted result(update)
GUI_P1 -> GUI_P1 : show result overlay\nrender final board

note over GUI_P1
Rematch requests, "End Match", room cleanup,
and navigation away from the result screen
are handled later by controller actions.
They are not automatic in this flow.
end note

@enduml
```
