# Submit Move, Validate, Apply Move, Send State Update (Refined for Current Code)

## About

This refined sequence matches the current core move pipeline:

- `GameSessionManager.submitMove(...)` performs session/player/turn checks, move validation, move application, end-condition evaluation, and final `MoveSubmissionResult` creation.
- `PlatformCore.submitMove(...)` publishes the returned event on the `EventBus`.
- In local play, the submitting game page updates from the returned `MoveSubmissionResult`.
- In network play, `MessageRouter.handleSubmitMove(...)` calls the same `PlatformCore.submitMove(...)` path, then broadcasts `GAME_STATE` separately after the move is accepted.
- This refined sequence focuses on the normal non-ending move path. The game-ending path is documented separately in `04.05 Game Ends Sequence (Refined)`.

## PlantUML Editor Code

```uml
@startuml
title Sequence - Submit Move -> Validate -> Apply Move -> Send State Update

actor Player as P1
participant "GUI\n(Game Page - P1)" as GUI_P1
participant "PlatformCore" as Core
participant "GameSessionManager" as GSM
participant "GameSession" as Session
participant "GameEngine" as Engine
participant "EventBus" as Bus

== Move Submission ==

P1 -> GUI_P1 : select move on board\nclick "Submit"
GUI_P1 -> Core : submitMove(sessionId, P1, move)
Core -> GSM : submitMove(sessionId, P1, move)

== Turn Verification ==

GSM -> Session : get session / state / players
Session --> GSM : session data

alt session missing / game already over / unknown player / not your turn / move is null
  GSM --> Core : MoveSubmissionResult.rejected(rejection)
  Core -> Bus : publish(MoveRejectedEvent)
  Bus --> Core : handle(MoveRejectedEvent)
  Core --> GUI_P1 : return rejected result
  GUI_P1 -> GUI_P1 : show rejection / no board change
else prechecks pass
end

== Move Validation ==

GSM -> Engine : validateMove(state.board, move)
Engine --> GSM : Validation

alt validation failed
  GSM --> Core : MoveSubmissionResult.rejected(rejection)
  Core -> Bus : publish(MoveRejectedEvent)
  Bus --> Core : handle(MoveRejectedEvent)
  Core --> GUI_P1 : return rejected result
  GUI_P1 -> GUI_P1 : flash rejected move / retry
else validation succeeded
end

== Apply Move ==

GSM -> Engine : applyMove(state.board, move)
Engine --> GSM : newBoard
GSM -> GSM : update stored board\nadd move to history

== Check End Conditions ==

GSM -> Engine : evaluateEnd(newBoard)
Engine --> GSM : gameOver?

alt gameOver == false
  GSM -> GSM : advance turn\nbuild GameStateUpdate(...)

  == Send State Update ==

  GSM --> Core : MoveSubmissionResult.accepted(update)
  Core -> Bus : publish(GameStateUpdate)
  Bus --> Core : handle(GameStateUpdate)

  == Update Game Page ==

  Core --> GUI_P1 : return accepted result(update)
  GUI_P1 -> GUI_P1 : render updated board\nupdate turn indicator
else gameOver == true
  note over GSM
    Continue in
    04.05 Game Ends Sequence
  end note
end

@enduml
```
