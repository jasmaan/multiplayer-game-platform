# Turn Notification While Player Is In Lobby/Dashboard (Refined for Iteration 1)

## About

Refined sequence showing how the platform routes turn notifications to players regardless of their current screen. Demonstrates the key architecture rule: game code emits events, `PlatformCore` decides routing based on each player's `PlayerContext`, and `NotificationService` pushes the message to whichever GUI controller has registered itself as the active `NotificationListener`.

## Owner: Platform Core Sub-team

## PlantUML Editor Code

```uml
@startuml
title Sequence - Turn Notification Routing (Refined)

actor "Player 1\n(in Lobby)" as P1
actor "Player 2\n(in Game)" as P2

participant "GUI\n(Dashboard - P1)\n<<NotificationListener>>" as LobbyGUI
participant "GUI\n(GamePage - P2)\n<<NotificationListener>>" as GameGUI
participant "PlatformCore" as Core
participant "GameSessionManager" as GSM
participant "GameEngine" as Engine
participant "EventBus" as Bus
participant "NotificationService" as Notify

== Player 2 Makes a Move (P1 is browsing lobby) ==

P2 -> GameGUI : select move, click Submit
GameGUI -> Core : submitMove(sessionId, P2, move)
Core -> GSM : submitMove(sessionId, P2, move)

GSM -> Engine : validateMove(state, move)
Engine --> GSM : Validation(NONE)

GSM -> Engine : applyMove(state, move)
Engine --> GSM : newState

GSM -> Engine : evaluateEnd(newState)
Engine --> GSM : false

GSM -> GSM : advanceTurn()\nactivePlayerId = P1

== Event Published ==

GSM -> Bus : publish(GameStateUpdate(\nactivePlayerId=P1,\nstatus=IN_PROGRESS,\ngameOver=false,\npayload=newState))

Bus --> Core : handle(GameStateUpdate)
Core -> Core : handleGameStateUpdate(update)

== PlatformCore Routes Based on Each Player's Context ==

Core -> Core : ctxP1 = playerContexts.get(P1)\n// DASHBOARD
Core -> Core : ctxP2 = playerContexts.get(P2)\n// IN_GAME

== Notify P1 (on Dashboard - it is now P1's turn) ==

Core -> Notify : createTurnAlert(P1, sessionId, ctxP1)
Notify -> Notify : notifyPlayer(P1,\n"[ALERT] Your turn is\nwaiting in session " + sessionId)
Notify -> LobbyGUI : listener.onNotification(P1, message)

LobbyGUI -> LobbyGUI : display banner/badge\nwith "Go to Game" button

== Notify P2 (already IN_GAME) ==

Core -> Notify : notifyPlayer(P2,\n"Game updated in session " + sessionId)
Notify -> GameGUI : listener.onNotification(P2, message)
GameGUI -> GameGUI : re-render board from\nsession state, disable input\n(waiting for P1)

== P1 Clicks Notification to Enter Game ==

P1 -> LobbyGUI : click "Go to Game" notification
LobbyGUI -> Core : navigate to game page (sessionId)
Core -> GSM : getSession(sessionId)
GSM --> Core : GameSession (current state)

Core --> LobbyGUI : load GamePage(sessionId, currentState)

note over LobbyGUI
  GUI transitions from Dashboard
  to GamePage. The GamePage controller
  registers itself as the new
  NotificationListener via
  NotificationService.setListener(this).
end note

@enduml
```
