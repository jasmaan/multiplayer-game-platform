# Overview

This sequence diagram shows the complete turn pipeline in the Session. 

It covers:

- Session lookup
- Turn verification
- Move validation and application
- End condition evaluation
- Turn advancement
- Event release

# Event Publishing
- "GameSessionManager.submitMove()" will return a "GameStateUpdate"
- "PlatformCore" will publish that event to the "EventBus"
- This allows for the Session layer to be independent

# State Mutation Rules

The state will be mutated only when a move is valid

This means that no state changes will occur if:
- SESSION_NOT_FOUND
- NOT_YOUR_TURN
- INVALID_MOVE

Instead, these cases will create a "MoveRejectedEvent," without modifying "GameState"

When the state change occurs on a valid move:
- Board is updated
- Move is recorded
- If the game is still going, the turn will advance
- Otherwise, the status will change to GAME_OVER

# GameStateUpdate Fields

- sessionId
- activePlayerId
- gameStatus
  - IN_PROGRESS
  - GAME_OVER
- moveResult
  - MOVE_ACCEPTED
  - GAME_OVER
- board
- winnerId

# When the Game Ends

- GameState status is set to GAME_OVER
- GameSession status is set to GAME_OVER
- endTime is recorded
- GameStateUpdate with gameOver = True is created

If any moves are attempted past this point, then a "GAME_ALREADY_OVER" error will be thrown.
