# Platform Core Use Case Descriptions (Refined for Iteration 1)

## About

These use case descriptions cover the Platform Core sub-team's owned interactions. They refine and expand the starter use cases (UC-05, UC-06, UC-08) and add new use cases for move submission, turn notification, game end, and room management.

## Team: Platform Core Sub-Team

---

## UC-05: Join Game Lobby (Refined)

**Primary actor:** Player
**Goal:** Enter a lobby/room for a specific game to wait for other players.
**Preconditions:** Player is authenticated; target game type exists on the platform.
**Trigger:** Player selects a game type and chooses "Join Lobby".

**Main success scenario:**
1. System retrieves available rooms for the selected game type via `RoomManager.getAvailableRooms(gameType)`.
2. System displays list of open rooms (showing player count, host name, room status).
3. Player selects a room (or system creates a new one if none are available).
4. `RoomManager.joinRoom(roomId, playerId)` is called.
5. System validates: room exists, room is not full, player is not already in the room.
6. Player is added to the room. Room status updates if now full.
7. System shows lobby view with current participants and lobby chat.
8. System broadcasts a player-joined notification to other room members.

**Alternative flows:**
- **5a. Room is full:** System returns `PlatformError.ROOM_FULL`. Player is prompted to select another room or create a new one.
- **5b. Player already in room:** System returns `PlatformError.PLAYER_ALREADY_IN_ROOM`. No action taken.
- **5c. Room not found:** System returns `PlatformError.ROOM_NOT_FOUND`. Room list is refreshed.

**Postconditions:** Player is in the selected room. Room player count is updated.

## UC-06: Enqueue for Next Available Game (Refined)A~~`
**Primary actor:** Player
**Goal:** Wait in a matchmaking queue to be paired with an appropriate opponent.
**Preconditions:** Player is authenticated; game type supports queueing; player is not already in a queue.
**Trigger:** Player selects a game type and clicks "Find Match" / "Enqueue".

**Main success scenario:**
1. `PlatformCore.joinQueue(playerId, gameType)` is called.
2. `MatchMaking.addPlayerToQueue(playerId, gameType)` adds player to the appropriate `PlayerQueue`.
3. System shows queue status (position in queue, estimated wait).
4. `MatchMaking.matchPlayers(gameType)` runs periodically or on new player arrival.
5. When enough players are matched (based on skill/rank proximity), `MatchFoundEvent` is published to `EventBus`.
6. `PlatformCore` consumes the event and notifies matched players via `NotificationService.createMatchFoundAlert()`.
7. System creates a room via `RoomManager.createRoom()` and assigns matched players.
8. `GameSessionManager.startSession()` initializes the game session.
9. Players are prompted to join the game.

**Alternative flows:**
- **2a. Player already in queue:** System returns `PlatformError.QUEUE_FAILED`. Player is informed.
- **4a. Player leaves queue before match:** `MatchMaking.removePlayer(playerId)` is called. Player returns to dashboard.
- **5a. Not enough players:** Players remain in queue. System continues waiting.

**Postconditions:** Player is either matched and in a game session, or still waiting in the queue.

## UC-08: Join Game Session (Refined)

**Primary actor:** Player
**Goal:** Enter the active game session once it is ready to start.
**Preconditions:** Player is authenticated; a game session has been created for the player (via matchmaking or room ready-up).
**Trigger:** Player receives "Game Ready" notification and selects "Join Game".

**Main success scenario:**
1. System verifies the player is assigned to the session via `GameSessionManager.getSession(sessionId)`.
2. System verifies session status is `STARTING` or `IN_PROGRESS`.
3. System connects the player to the game view.
4. `GameEngine.createInitialState(players)` is called (if first player joining triggers start).
5. `GameStateUpdate` is published with initial board state and first active player.
6. System displays the game board, turn indicator, and player info.

**Alternative flows:**
- **1a. Player not in session:** System returns `PlatformError.INVALID_SESSION`. Player returns to dashboard.
- **2a. Session already over:** System returns `PlatformError.GAME_ALREADY_OVER`. Player sees result summary.

**Postconditions:** Player is in the active game view. Game is in progress.

## UC-09: Submit Move (New)

**Primary actor:** Player
**Goal:** Make a move during their turn in an active game.
**Preconditions:** Player is authenticated; player is in an active game session; it is the player's turn.
**Trigger:** Player selects a move on the game board and clicks "Submit".

**Main success scenario:**
1. GUI sends `PlatformCore.submitMove(sessionId, playerId, move)`.
2. `PlatformCore` delegates to `GameSessionManager.submitMove(sessionId, playerId, move)`.
3. `GameSessionManager` verifies it is the player's turn via `isPlayerTurn()`.
4. `GameSessionManager` calls `GameEngine.validateMove(state, move)` → returns `Validation`.
5. Move is valid (`Validation.isValid() == true`). `GameSessionManager` calls `GameEngine.applyMove(state, move)`.
6. New state is returned. `GameSessionManager` calls `GameEngine.evaluateEnd(newState)`.
7. Game is not over. `GameState.advanceTurn()` switches to next player.
8. `GameSessionManager` returns `MoveSubmissionResult.accepted(gameStateUpdate)` to `PlatformCore`. `PlatformCore` publishes `GameStateUpdate` to `EventBus`.
9. `PlatformCore` consumes the event:
   - Updates the current player's GUI (disable input, show updated board).
   - Notifies the next player (enable input if in-game, or send turn alert if in lobby).

**Alternative flows:**
- **3a. Not player's turn:** `GameSessionManager` returns `MoveSubmissionResult.rejected(...)` with `PlatformError.NOT_YOUR_TURN`. `PlatformCore` publishes `MoveRejectedEvent`. GUI shows error.
- **4a. Invalid move:** `Validation.isValid() == false`. `GameSessionManager` returns `MoveSubmissionResult.rejected(...)` with `PlatformError.INVALID_MOVE`. `PlatformCore` publishes `MoveRejectedEvent`. GUI shows error, player retries.
- **6a. Game is over:** Flow continues to UC-11 (Game End).

**Postconditions:** Board is updated. Turn has advanced to the next player (or game has ended).

## UC-10: Receive Turn Notification (New)

**Primary actor:** Player (passive recipient)
**Goal:** Be notified that it is their turn, regardless of current screen.
**Preconditions:** Player is authenticated; player is in an active game session; opponent has just completed their turn.
**Trigger:** `GameStateUpdate` is published with `activePlayerId` set to this player.

**Main success scenario:**
1. `EventBus` delivers `GameStateUpdate` to `PlatformCore`.
2. `PlatformCore` checks the recipient player's current context (in-game view vs. lobby/dashboard).
3. **If player is on the game screen:**
   - GUI receives `onGameStateUpdate()`: board is re-rendered, input is enabled.
4. **If player is in the lobby/dashboard:**
   - `NotificationService.createTurnAlert(playerId, sessionId)` is called.
   - Lobby/Dashboard GUI shows a banner/badge: "Your turn in [Game Name]!"
   - Player can click the notification to navigate to the game view.

**Alternative flows:**
- **2a. Player is disconnected (stubbed):** Notification is queued. On reconnect, player receives pending alerts.

**Postconditions:** Player is aware it is their turn. If in-game, input is enabled.

## UC-11: Game Ends (New)

**Primary actor:** System (triggered by game logic)
**Goal:** Finalize the game session, record results, and return players to dashboard.
**Preconditions:** A game session is in progress; a terminal condition has been detected by `GameEngine.evaluateEnd()`.
**Trigger:** `GameEngine.evaluateEnd(state)` returns true after a move is applied.

**Main success scenario:**
1. `GameSessionManager` detects game over from `evaluateEnd()`.
2. `GameEngine.getWinner(state)` determines the winner (or draw).
3. `GameSessionManager` sets session status to `GAME_OVER`.
4. `GameSessionManager` calls `Leaderboard.logGameResult(sessionId, winnerId, loserId, isDraw)`.
5. `Leaderboard` updates player rankings via `updatePlayerRanking()` and persists to `Database` stub.
6. `GameSessionManager` publishes final `GameStateUpdate` with `status=GAME_OVER`, `winnerId`, and result info.
7. `PlatformCore` consumes the event and notifies all players via `NotificationService.createGameOverAlert()`.
8. GUI displays win/lose/draw result screen.
9. Players click "Return to Dashboard" which calls `PlatformCore.returnToDashboard()`.
10. `RoomManager.closeRoom(roomId)` closes the associated room.

**Alternative flows:**
- **4a. Stats persistence fails (stub):** System logs warning but does not block game-over flow.

**Postconditions:** Game session is closed. Player stats and leaderboard are updated. Players are back on the dashboard.

## UC-12: Create Room (New)

**Primary actor:** Player
**Goal:** Create a new game room/lobby to host a match.
**Preconditions:** Player is authenticated.
**Trigger:** Player selects a game type and clicks "Create Room".

**Main success scenario:**
1. `PlatformCore` delegates to `RoomManager.createRoom(hostId, gameType, maxPlayers)`.
2. A new `Room` is created with status `OPEN` and the player as host.
3. System displays the room lobby view.
4. Other players can discover and join this room via UC-05.
5. When room reaches minimum players, `RoomManager.isRoomReady()` returns true.
6. Host can start the game, triggering `GameSessionManager.startSession()`.

**Postconditions:** Room exists and is visible to other players. Host is in the room.

---

## UC-13: Leave Room (New)

**Primary actor:** Player
**Goal:** Exit a room/lobby before the game starts.
**Preconditions:** Player is in a room; game has not started yet (room status is OPEN or FULL).
**Trigger:** Player clicks "Leave Room".

**Main success scenario:**
1. `RoomManager.leaveRoom(roomId, playerId)` is called.
2. Player is removed from the room.
3. Room status updates (e.g., FULL -> OPEN if a slot opened).
4. Remaining players are notified of the departure.
5. Player returns to the dashboard/lobby browser.
6. If the host leaves, host role is transferred to the next player (or room is closed if empty).

**Alternative flows:**
- **1a. Player not in room:** System returns `PlatformError.PLAYER_NOT_IN_ROOM`. No action taken.
- **6a. Room is now empty:** `RoomManager.closeRoom(roomId)` is called. Room is removed.

**Postconditions:** Player is no longer in the room. Room state is updated.
