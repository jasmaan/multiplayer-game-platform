# Platform Core Interface Contracts

**Owner:** Platform Core Sub-team
**Iteration:** 2 (Implementation — Integration/phase2-networking)
**Last Updated:** 2026-04-10

---

## Overview

This document defines the formal interface contracts between **Platform Core** and every external sub-team that integrates with it. Platform Core (`PlatformCore`) is the single entry point for all UI interactions and the sole consumer of all game events. No sub-team calls another sub-team directly — all cross-boundary communication is brokered by PlatformCore or the EventBus.

### Architecture Rule (Non-Negotiable)

```
UI Sub-team  ──calls──►  PlatformCore  ──delegates──►  Internal Services
                                ▲
Game Sub-team  ──publishes──►  EventBus  ──delivers──►  PlatformCore
```

- **UI** calls PlatformCore methods and receives callbacks via `NotificationService`.
- **Game engines** implement the `GameEngine` interface and never call PlatformCore directly.
- **Rules/Validation** logic is encapsulated inside `GameEngine` implementations.
- **PlatformCore** is the only component that reads `PlayerContext` and decides notification routing.

## Contract 1: PlatformCore ↔ UI Sub-team

The UI sub-team interacts exclusively through `PlatformCore` public methods. The UI must never access `GameSessionManager`, `MatchMaking`, `RoomManager`, or `EventBus` directly.

### 1.1 Authentication

#### `validateCredentials(firstName: String, lastName: String, password: String): Validation`

| Field | Detail |
|-------|--------|
| **Called by** | `RegistrationPage` on form submit, before `registerPlayer()` |
| **Returns** | `Validation.success()` if inputs pass all rules; `Validation.failure(errorCode, message)` otherwise |
| **Rules** | `firstName`/`lastName` must match `^[a-zA-Z][a-zA-Z '-]{1,49}$`; password must be 8–64 chars with upper, lower, digit, and special char |
| **UI responsibility** | Check `validation.isValid()` and display `validation.getMessage()` on failure before calling `registerPlayer()` |

#### `registerPlayer(firstName: String, lastName: String, password: String): String`

| Field                        | Detail                                                                                          |
| ---------------------------- | ----------------------------------------------------------------------------------------------- |
| **Called by**                | `RegistrationPage` after `validateCredentials()` returns success                                |
| **Preconditions**            | Credentials already validated; `firstName`, `lastName`, and `password` are non-null             |
| **Postconditions (success)** | New `PlayerProfile` persisted to `data/users.json`; credentials hashed (SHA-256) and persisted to `data/credentials.json`; returns the generated username |
| **Postconditions (failure)** | No state change; returns `null`                                                                 |
| **Username format**          | `{firstInitial}{lastName}{n}` (e.g. `jdoe1`). PlatformCore derives and guarantees uniqueness. UI does not control format. |
| **UI responsibility**        | Display error message on `null`; navigate to `LoginPage` on non-null return                     |

#### `login(username: String, password: String): boolean`

| Field | Detail |
|-------|--------|
| **Called by** | `LoginPage` on form submit |
| **Preconditions** | `username` and `password` are non-null, non-empty |
| **Postconditions (success)** | Player context set to `DASHBOARD`; `getCurrentUser()` returns `username` |
| **Postconditions (failure)** | No state change; returns `false` |
| **Error cases** | Credentials not found → `false`; player already logged in → `false` |
| **UI responsibility** | Display error message on `false`; navigate to `Dashboard` on `true` |

#### `logout(playerId: String): void`

| Field | Detail |
|-------|--------|
| **Called by** | Any screen with a logout button |
| **Preconditions** | Player is logged in (`isPlayerLoggedIn(playerId) == true`) |
| **Postconditions** | Player removed from context map; auto-removed from matchmaking queue if `IN_QUEUE` |
| **Error cases** | Silently no-ops if player is not logged in |
| **UI responsibility** | Navigate back to `LoginPage` after calling logout |

#### `getCurrentUser(): String`

| Field | Detail |
|-------|--------|
| **Returns** | The currently logged-in player ID, or `null` if no one is logged in |
| **Called by** | Any screen that needs to identify the local player |

### 1.2 Matchmaking

#### `joinQueue(playerId: String, gameType: String): void`

| Field | Detail |
|-------|--------|
| **Called by** | `Dashboard` when player clicks "Find Match" |
| **Preconditions** | Player is logged in and context is `DASHBOARD` or `IN_LOBBY` |
| **Postconditions** | Player context set to `IN_QUEUE`; player added to matchmaking queue for `gameType` |
| **UI responsibility** | Show queue status indicator; listen for `MatchFoundAlert` notification |

#### `leaveQueue(playerId: String): void`

| Field | Detail |
|-------|--------|
| **Called by** | `Dashboard` when player clicks "Leave Queue" |
| **Preconditions** | Player context is `IN_QUEUE` |
| **Postconditions** | Player removed from queue; context reset to `DASHBOARD` |
| **UI responsibility** | Hide queue status indicator and return player to dashboard view |

---

### 1.3 Move Submission

#### `submitMove(sessionId: String, playerId: String, move: Object): MoveSubmissionResult`

| Field | Detail |
|-------|--------|
| **Called by** | `GamePage` when player clicks "Submit" on the board |
| **Preconditions** | `sessionId` references an active session; `playerId` is a participant |
| **Postconditions (success)** | `GameStateUpdate` published to `EventBus`; all recipients notified; returns `MoveSubmissionResult` with `isAccepted() == true` |
| **Postconditions (failure)** | `MoveRejectedEvent` published; returns `MoveSubmissionResult` with `isAccepted() == false` |
| **Returns** | `MoveSubmissionResult` — call `isAccepted()`, then `getUpdate()` or `getRejection()` accordingly; `null` only if the session is not found |
| **UI responsibility** | Do not re-enable input until a `GameStateUpdate` or `MoveRejectedEvent` notification arrives |

---

### 1.4 Chat

#### `sendChatMessage(sessionId: String, senderId: String, text: String): void`

| Field | Detail |
|-------|--------|
| **Called by** | `GamePage` chat input on submit |
| **Preconditions** | `sessionId` references an active session; `senderId` is a participant; `text` passes `ChatValidator` |
| **Postconditions** | `ChatMessageEvent` published to `EventBus`; registered per-session chat callback fires on all recipients |
| **Validation** | PlatformCore silently no-ops if `ChatValidator` rejects the message (banned words check) |
| **UI responsibility** | Display message in chat panel via the callback registered with `PlatformCore` |

---

### 1.5 Navigation

#### `returnToDashboard(playerId: String): void`

| Field | Detail |
|-------|--------|
| **Called by** | `ResultsPage` when player clicks "Return to Dashboard" |
| **Preconditions** | Player is logged in |
| **Postconditions** | Player context set to `DASHBOARD`; room and session cleanup triggered by PlatformCore |
| **UI responsibility** | Navigate to `Dashboard` view after calling this method |

### 1.6 Notifications Delivered to UI

The UI receives asynchronous notifications via `NotificationService`. The UI sub-team must register listeners or observe these notification calls.

| Notification Method | Trigger | UI Action |
|---------------------|---------|-----------|
| `notifyPlayer(playerId, message)` | General alert (move rejected, system message) | Show inline error or toast |
| `createTurnAlert(playerId, sessionId)` | Player's turn while they are on dashboard or in lobby | Show banner/badge with "Your turn in [game]" |
| `createGameOverAlert(playerId, result)` | Game session ended | Show result overlay ("You won!" / "You lost.") |
| `createMatchFoundAlert(playerId, roomId)` | Matchmaking found a match | Show popup "Match found! Joining game…"; navigate to `GamePage` |

**Contract:** PlatformCore guarantees that notification methods are called with non-null `playerId`. The UI must handle duplicate notifications gracefully (e.g., if a player receives two turn alerts, display only one).

## Contract 2: PlatformCore ↔ Game Sub-team (GameEngine Interface)

Game sub-teams must implement the `GameEngine` interface. They do **not** interact with PlatformCore directly. Their implementation is registered via `GameSessionManager.registerEngine(gameType, engine)`.

### 2.1 GameEngine Interface

```java
public interface GameEngine {
    Object createInitialState(List<String> players);
    Validation validateMove(Object state, Object move);  // returns Validation, not boolean
    Object applyMove(Object state, Object move);
    boolean evaluateEnd(Object state);
    String getWinner(Object state);
}
```

#### `createInitialState(players: List<String>): Object`

| Field | Detail |
|-------|--------|
| **Called by** | `GameSessionManager.startSession()` on session creation |
| **Preconditions** | `players` is non-null; size ≥ 2 |
| **Returns** | A non-null object representing the initial board/game state |
| **Contract** | The returned state must encode the starting active player (first in `players` list by convention) |
| **Game sub-team responsibility** | Define and document the shape of the returned state object |

#### `validateMove(state: Object, move: Object): Validation`

| Field | Detail |
|-------|--------|
| **Called by** | `GameSessionManager.submitMove()` after turn-order verification |
| **Preconditions** | `state` is a valid state object returned by `createInitialState` or `applyMove`; `move` is non-null |
| **Returns** | `Validation.success()` if the move is legal; `Validation.failure(errorCode, message)` otherwise |
| **Contract** | Must be a pure function — no side effects, no state mutation |
| **On failure** | `GameSessionManager` creates a `MoveRejectedEvent`; `PlatformCore` publishes it to `EventBus` |

#### `applyMove(state: Object, move: Object): Object`

| Field | Detail |
|-------|--------|
| **Called by** | `GameSessionManager.submitMove()` only after `validateMove` returns `true` |
| **Preconditions** | Move has already been validated |
| **Returns** | A new state object with the move applied |
| **Contract** | Must not mutate the input `state`; return a new state object |

#### `evaluateEnd(state: Object): boolean`

| Field | Detail |
|-------|--------|
| **Called by** | `GameSessionManager.submitMove()` after `applyMove` |
| **Returns** | `true` if the game is over (win, loss, or draw); `false` to continue |
| **Contract** | Must be deterministic given the same state |

#### `getWinner(state: Object): String`

| Field | Detail |
|-------|--------|
| **Called by** | `GameSessionManager` only when `evaluateEnd` returns `true` |
| **Returns** | The `playerId` of the winner, or `null` for a draw |
| **Contract** | Behavior is undefined if called before `evaluateEnd` returns `true` |

### 2.2 Engine Registration

Game sub-teams must register their engine with `GameSessionManager` before any session of their game type can be started:

```java
// Example — called during application startup
GameEngine chessEngine = new ChessEngine();
platformCore.getSessionManager().registerEngine("chess", chessEngine);
```

- The `gameType` key (e.g., `"chess"`) must exactly match the string used in `joinQueue(playerId, gameType)` and `RoomManager.createRoom(hostId, gameType, maxPlayers)`.
- If no engine is registered for a `gameType`, `GameSessionManager.startSession()` will throw/return an error — **the game sub-team is responsible for registering before any player can queue**.

## Contract 3: PlatformCore ↔ Rules/Validation Sub-team

Rules and move validation are fully encapsulated inside the `GameEngine` implementation (see Contract 2). There is no separate Rules/Validation API boundary — the game sub-team owns both the engine and its validation logic.

**What PlatformCore guarantees to the Rules layer:**

| Guarantee | Detail |
|-----------|--------|
| Turn ordering | `validateMove` is only called when it is the submitting player's turn. PlatformCore/GameSessionManager performs the turn check before invoking the engine. |
| State consistency | `applyMove` is only called after `validateMove` returns `true`. The engine will never receive an `applyMove` call for an invalid move. |
| Session validity | `validateMove` is only called on active, non-terminated sessions. |

**What the Rules layer must guarantee to PlatformCore:**

| Guarantee | Detail |
|-----------|--------|
| No external calls | `GameEngine` implementations must not call `PlatformCore`, `EventBus`, or any UI component |
| Pure validation | `validateMove` must not modify state |
| Null safety | `getWinner` must return `null` (not throw) for draws |

## Contract 4: Event Payload Contracts

These are the shared data structures that cross sub-team boundaries via the `EventBus`. All sub-teams must treat these as read-only after publication.

### `GameStateUpdate`

Published by: `GameSessionManager`
Consumed by: `PlatformCore` (via EventBus subscription)

| Field | Type | Description |
|-------|------|-------------|
| `sessionId` | `String` | Identifies the active game session |
| `recipients` | `List<String>` | Player IDs who should receive this update |
| `status` | `GameStatus` | Current game status (`IN_PROGRESS`, `GAME_OVER`, etc.) |
| `activePlayerId` | `String` | Player whose turn it now is |
| `previousPlayerId` | `String` | Player who just moved |
| `payload` | `Object` | Game-specific board/state data (defined by GameEngine) |
| `isGameOver` | `boolean` | `true` if the game has ended |
| `winnerId` | `String` | Winner's player ID, or `null` for draws (only valid when `isGameOver=true`) |

### `MoveRejectedEvent`

Published by: `GameSessionManager`
Consumed by: `PlatformCore`

| Field | Type | Description |
|-------|------|-------------|
| `sessionId` | `String` | Session where rejection occurred |
| `playerId` | `String` | Player whose move was rejected |
| `reason` | `PlatformError` | `NOT_YOUR_TURN` or `INVALID_MOVE` |
| `message` | `String` | Human-readable description of the rejection |

### `MatchFoundEvent`

Published by: `MatchMaking` (via `PlatformCore.tryMatch()`)
Consumed by: `PlatformCore`

| Field | Type | Description |
|-------|------|-------------|
| `players` | `List<String>` | The matched player IDs |
| `gameType` | `String` | The game type they were queued for |
| `roomId` | `String` | The room pre-created for them |

### `RoomJoinedEvent`

Published by: `PlatformCore`
Consumed by: `PlatformCore`

| Field | Type | Description |
|-------|------|-------------|
| `roomId` | `String` | The room that was joined |
| `playerId` | `String` | The player who joined |

### `ChatMessageEvent`

Published by: `PlatformCore`
Consumed by: `PlatformCore` (delivers to per-session registered callback)

| Field | Type | Description |
|-------|------|-------------|
| `sessionId` | `String` | The session in which the chat occurred |
| `senderId` | `String` | The player who sent the message |
| `text` | `String` | The validated message text |

## Contract 5: Error Codes

All errors from Platform Core operations are expressed via the `PlatformError` enum. Sub-teams must not define their own error types for platform-level failures.

| Error Code | Produced By | Meaning |
|------------|-------------|---------|
| `ROOM_FULL` | `RoomManager` | Attempt to join a full room |
| `ROOM_NOT_FOUND` | `RoomManager` | Room ID does not exist |
| `PLAYER_ALREADY_IN_ROOM` | `RoomManager` | Player is already in this room |
| `PLAYER_NOT_IN_ROOM` | `RoomManager` | Player is not in this room |
| `INVALID_SESSION` | `GameSessionManager` | Session ID not found |
| `INVALID_MOVE` | `GameSessionManager` | Move failed `GameEngine.validateMove()` |
| `NOT_YOUR_TURN` | `GameSessionManager` | Submitting player is not the active player |
| `GAME_ALREADY_OVER` | `GameSessionManager` | Move submitted to a terminated session |
| `AUTH_FAILED` | `PlatformCore` | Login credential mismatch |
| `QUEUE_FAILED` | `MatchMaking` | Player could not be added to queue |
