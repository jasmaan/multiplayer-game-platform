# Event Consumption & Payload Specification

**Owners:** Platform Core Sub-team
**Iteration:** 1 (Design Phase)
**Last Updated:** 2026-02-24

---

## Purpose

This document is the co-designed specification for the event-driven contract between:

- **Event system** — owns the `EventBus`, event class hierarchy, and `NotificationService` routing logic
- **Platform core** — owns `PlatformCore`, which subscribes to all events and decides how to respond

It defines:
1. Which events exist, who publishes them, and what their payloads contain
2. Which events `PlatformCore` subscribes to and with which type key strings
3. What `PlatformCore` does when each event is received
4. How `NotificationService` routes notifications based on `PlayerContext`
5. Example payloads for all four core scenarios

---

## 1. Event System Architecture

```
Publishers                  EventBus              Consumer           Output
──────────────────────────────────────────────────────────────────────────────
GameSessionManager  ──────► "GameStateUpdate" ──► PlatformCore ──► NotificationService
GameSessionManager  ──────► "MoveRejected"    ──► PlatformCore ──► NotificationService
MatchMaking         ──────► "MatchFound"      ──► PlatformCore ──► NotificationService
```

**Architecture rules:**
- `GameSessionManager` and `MatchMaking` **only publish** — they never subscribe
- `PlatformCore` is the **only subscriber** for all event types
- `NotificationService` is called **only by PlatformCore** — never directly by publishers
- The EventBus routes by `event.getEventType()` which is set in each event's constructor via `super(eventId, eventType)`

---

## 2. Subscription Registry

`PlatformCore` registers these subscriptions at construction time:

| Event Type Key | Subscriber | Registered In |
|----------------|-----------|---------------|
| `"GameStateUpdate"` | `PlatformCore` | `PlatformCore` constructor |
| `"MoveRejected"` | `PlatformCore` | `PlatformCore` constructor |
| `"MatchFound"` | `PlatformCore` | `PlatformCore` constructor |

```java
// PlatformCore constructor — actual subscription code
this.eventBus.subscribe("GameStateUpdate", this);
this.eventBus.subscribe("MoveRejected", this);
this.eventBus.subscribe("MatchFound", this);
```

**Critical constraint:** The event type key string passed to `subscribe()` must exactly match the string passed to `super()` in the event class constructor. Mismatches cause silent delivery failure.

| Event Class | Constructor Call | Resulting Key |
|-------------|-----------------|---------------|
| `GameStateUpdate` | `super(eventId, "GameStateUpdate")` | `"GameStateUpdate"` ✅ |
| `MoveRejectedEvent` | `super(eventId, "MoveRejected")` | `"MoveRejected"` ✅ |
| `MatchFoundEvent` | `super(eventId, "MatchFound")` | `"MatchFound"` ✅ |

## 3. Event Hierarchy

```
GameEvent (abstract)
 ├── GameStateUpdate        published by: GameSessionManager
 ├── MoveRejectedEvent      published by: GameSessionManager
 └── MatchFoundEvent        published by: MatchMaking
```

### `GameEvent` (abstract base)

| Field | Type | Description |
|-------|------|-------------|
| `eventId` | `String` | Unique identifier — use `UUID.randomUUID().toString()` |
| `timestamp` | `long` | Unix ms timestamp — use `System.currentTimeMillis()` |
| `eventType` | `String` | Routing key used by EventBus — set via `super()` |

## 4. Event Payload Specifications

### 4.1 `GameStateUpdate`

**Publisher:** `GameSessionManager`
**Event type key:** `"GameStateUpdate"`
**When published:** After every accepted move; after game over is detected

| Field | Type | Nullable | Description |
|-------|------|----------|-------------|
| `sessionId` | `String` | No | ID of the active game session |
| `recipients` | `List<String>` | No | All player IDs who should receive this update |
| `status` | `GameStatus` | No | `IN_PROGRESS` or `GAME_OVER` |
| `activePlayerId` | `String` | No | Player whose turn it now is |
| `previousPlayerId` | `String` | No | Player who just moved |
| `payload` | `Object` | No | Game-specific board state (defined by the GameEngine implementation) |
| `moveResult` | `String` | No | `"MOVE_ACCEPTED"` or `"GAME_OVER"` |
| `gameOver` | `boolean` | No | `true` if the game has ended |
| `winnerId` | `String` | Yes | Winner's player ID; `null` for draw; only meaningful when `gameOver=true` |

---

### 4.2 `MoveRejectedEvent`

**Publisher:** `GameSessionManager`
**Event type key:** `"MoveRejected"`
**When published:** When a submitted move fails turn verification or engine validation

| Field | Type | Nullable | Description |
|-------|------|----------|-------------|
| `sessionId` | `String` | No | ID of the session where rejection occurred |
| `playerId` | `String` | No | Player whose move was rejected |
| `reason` | `PlatformError` | No | `NOT_YOUR_TURN` or `INVALID_MOVE` |
| `message` | `String` | No | Human-readable description (e.g., `"Illegal move: position already taken"`) |

---

### 4.3 `MatchFoundEvent`

**Publisher:** `MatchMaking`
**Event type key:** `"MatchFound"`
**When published:** When matchmaking successfully pairs two or more players

| Field | Type | Nullable | Description |
|-------|------|----------|-------------|
| `players` | `List<String>` | No | Matched player IDs (minimum 2) |
| `gameType` | `String` | No | The game type they were queued for (e.g., `"chess"`) |
| `roomId` | `String` | No | ID of the room pre-created for this match |

## 5. Scenario Payloads and Consumption Logic

### Scenario A: Move Accepted (Turn Changes)

**Trigger:** Player A submits a valid move; it is now Player B's turn.

**Published event:**
```java
new GameStateUpdate(
    UUID.randomUUID().toString(),   // eventId
    "session-001",                  // sessionId
    List.of("playerA", "playerB"), // recipients
    GameStatus.IN_PROGRESS,        // status
    "playerB",                     // activePlayerId  (turn advanced)
    "playerA",                     // previousPlayerId
    <boardObject>,                 // payload (engine-defined)
    "MOVE_ACCEPTED",               // moveResult
    false,                         // gameOver
    null                           // winnerId
)
```

**PlatformCore consumption — `handleGameStateUpdate()`:**

| Recipient | PlayerContext | Action taken |
|-----------|--------------|--------------|
| `playerA` | `IN_GAME` | `notifyPlayer(playerA, "Game updated in session-001")` — board refreshes, input disabled |
| `playerB` | `IN_GAME` | `notifyPlayer(playerB, "Game updated in session-001")` — board refreshes, input enabled |
| `playerB` | `DASHBOARD` or `IN_LOBBY` | `createTurnAlert(playerB, "session-001")` — banner/badge shown |

---

### Scenario B: Move Rejected

**Trigger:** Player A submits an invalid move (wrong turn or illegal position).

**Published event — NOT_YOUR_TURN:**
```java
new MoveRejectedEvent(
    UUID.randomUUID().toString(),   // eventId
    "session-001",                  // sessionId
    "playerA",                      // playerId
    PlatformError.NOT_YOUR_TURN,   // reason
    "Not your turn"                 // message
)
```

**Published event — INVALID_MOVE:**
```java
new MoveRejectedEvent(
    UUID.randomUUID().toString(),   // eventId
    "session-001",                  // sessionId
    "playerA",                      // playerId
    PlatformError.INVALID_MOVE,    // reason
    "Illegal move: position already taken" // message
)
```

**PlatformCore consumption — `handleMoveRejected()`:**

| Recipient | PlayerContext | Action taken |
|-----------|--------------|--------------|
| `playerA` | `IN_GAME` | `notifyPlayer(playerA, "Move rejected: <message>")` — inline error shown; input stays enabled for retry |

---

### Scenario C: Match Found

**Trigger:** Matchmaking pairs Player A and Player B.

**Published event:**
```java
new MatchFoundEvent(
    UUID.randomUUID().toString(),        // eventId
    List.of("playerA", "playerB"),      // players
    "chess",                             // gameType
    "room-abc-123"                       // roomId
)
```

**PlatformCore consumption — `handleMatchFound()`:**

| Recipient | PlayerContext (before) | Action taken | PlayerContext (after) |
|-----------|----------------------|--------------|----------------------|
| `playerA` | `IN_QUEUE` | `createMatchFoundAlert(playerA, "room-abc-123")` — popup shown | `IN_GAME` |
| `playerB` | `IN_QUEUE` | `createMatchFoundAlert(playerB, "room-abc-123")` — popup shown | `IN_GAME` |

---

### Scenario D: Game Over

**Trigger:** Player A's move triggers `GameEngine.evaluateEnd()` → `true`.

**Published event:**
```java
new GameStateUpdate(
    UUID.randomUUID().toString(),        // eventId
    "session-001",                       // sessionId
    List.of("playerA", "playerB"),      // recipients
    GameStatus.GAME_OVER,               // status
    "playerA",                           // activePlayerId (last active)
    "playerA",                           // previousPlayerId
    <finalBoardObject>,                  // payload
    "GAME_OVER",                         // moveResult
    true,                                // gameOver
    "playerA"                            // winnerId (null if draw)
)
```

**PlatformCore consumption — `handleGameStateUpdate()` when `isGameOver=true`:**

| Recipient | Result | Action taken | PlayerContext (after) |
|-----------|--------|--------------|----------------------|
| `playerA` (winner) | `"You won!"` | `createGameOverAlert(playerA, "You won!")` | `VIEWING_RESULTS` |
| `playerB` (loser) | `"You lost."` | `createGameOverAlert(playerB, "You lost.")` | `VIEWING_RESULTS` |

## 6. Notification Routing Decision Table

Full routing matrix combining all event types with all `PlayerContext` values:

| Event | Condition | PlayerContext | Notification Called | UI Effect |
|-------|-----------|--------------|---------------------|-----------|
| `GameStateUpdate` | `isGameOver=true` | Any | `createGameOverAlert(playerId, result)` | Result overlay shown |
| `GameStateUpdate` | `isGameOver=false`, player is active | `IN_GAME` | `notifyPlayer(playerId, "Game updated...")` | Board refreshes, input enabled |
| `GameStateUpdate` | `isGameOver=false`, player is active | `DASHBOARD` / `IN_LOBBY` | `createTurnAlert(playerId, sessionId)` | Banner/badge: "Your turn in [session]" |
| `GameStateUpdate` | `isGameOver=false`, player is active | `IN_QUEUE` | `createTurnAlert(playerId, sessionId)` | Banner/badge (player can navigate to game) |
| `GameStateUpdate` | `isGameOver=false`, player is not active | `IN_GAME` | `notifyPlayer(playerId, "Game updated...")` | Board refreshes, input disabled (waiting) |
| `GameStateUpdate` | `isGameOver=false`, player is not active | `DASHBOARD` / `IN_LOBBY` | *(no notification)* | No action needed |
| `MoveRejectedEvent` | Any | `IN_GAME` | `notifyPlayer(playerId, "Move rejected: <message>")` | Inline error; input stays enabled |
| `MoveRejectedEvent` | Any | Other | *(unexpected state — log warning)* | No UI action |
| `MatchFoundEvent` | Any | `IN_QUEUE` | `createMatchFoundAlert(playerId, roomId)` | Match popup; context → `IN_GAME` |
| `MatchFoundEvent` | Any | Other | `createMatchFoundAlert(playerId, roomId)` | Banner shown; context → `IN_GAME` |

## 7. Delivery Model

| Property | Current Behaviour | Deferred To |
|----------|------------------|-------------|
| Delivery order | Synchronous — handlers invoked in subscription order | N/A (acceptable for Iter 1–2) |
| Thread safety | Single-threaded — no synchronization on `subscribers` map | Iteration 3 |
| Error isolation | No — a throwing handler blocks subsequent handlers | Iteration 3 |
| Duplicate delivery | Not possible — each handler registered once per type | N/A |

**Agreed constraint:** `PlatformCore.handle()` must not throw exceptions. All errors must be caught internally to avoid blocking the EventBus delivery loop.

## 8. Open Questions / Agreed Decisions

| # | Question | Decision |
|---|----------|----------|
| 1 | Who generates `eventId`? | Caller uses `UUID.randomUUID().toString()` at publish time |
| 2 | `MatchFoundEvent.roomId` — who creates the room first? | `MatchMaking` creates the room via `RoomManager` before publishing the event, then passes the `roomId` into `MatchFoundEvent` |
| 3 | Is synchronous EventBus delivery acceptable? | Yes — deferred to Iteration 3 for async/thread-safety |
| 4 | Can there be multiple subscribers per event type? | Yes — EventBus supports it, but only `PlatformCore` subscribes in Iteration 1–2 |
| 5 | What if `recipients` list is empty on `GameStateUpdate`? | `handleGameStateUpdate()` iterates an empty list — no-op, no crash |
