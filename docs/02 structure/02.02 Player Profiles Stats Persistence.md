# 02 - Player, Profiles, Stats, Persistence

## About this diagram

This diagram models player identity and long-lived data. It covers player accounts, statistics, rankings, and persistence mechanisms. These classes store and retrieve information about players and their performance across games.

**Last Updated:** 2026-04-10 (reflects Iteration 2 implementation — `PlayerProfile` replaces the original `Player`/`PlayerStats`/`GeneralStats` design)

**Key implementation changes from original design:**
- `Player`, `PlayerStats`, `GeneralStats` were merged into a single `PlayerProfile` class in `core/`
- `CredentialsDatabase` stub replaced by `CredentialsRepository` (JSON-backed) + `UserRepository` (JSON-backed)
- `Rank` is not an enum — `PlayerProfile.currentRank` is a `String` with 3 tiers: Bronze / Silver / Gold (thresholds: Silver ≥ 600 MMR, Gold ≥ 800 MMR)
- MMR is tracked per game type via `mmrByGame: Map<String, Integer>`
- `PlayerProfileDTO` is a Jackson-annotated transfer object used for JSON serialization only

## Rank Tier Reference

| Tier | MMR Range | Adjustment |
|------|-----------|------------|
| Bronze | 0 – 599 | +25 win / −15 loss / +5 draw |
| Silver | 600 – 799 | same |
| Gold | 800+ | same |

Tier is recomputed on every `updatePlayerRanking()` call and stored in `PlayerRanking.tier` (in `Database`) and also written back to `PlayerProfile.currentRank` by `PlatformCore` at startup via `updatePlayerRankingToMmr()`.
