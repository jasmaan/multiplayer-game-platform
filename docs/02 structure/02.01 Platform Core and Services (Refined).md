# 01 - Platform Core & Services (Refined for Iteration 2)

## About this diagram

This is the refined comprehensive class diagram for the Platform Core sub-team. It defines all components owned by the Platform Core: session lifecycle, room/lobby management, matchmaking, rankings, event routing, and persistence. All games and UI interactions flow through these services. Game logic emits state updates consumed by PlatformCore, which decides how and when players are notified.

**Last Updated:** 2026-04-10 (reflects Iteration 2 / Integration/phase2-networking implementation)

**Refinements from Iteration 1:**
- `PlatformCore` expanded with `CredentialsRepository`, `UserRepository`, `PresenceService`, `PlayerProfile`, SHA-256 password hashing, and play-again coordination
- `GameEngine.validateMove()` now returns `Validation` (not `boolean`) — carries error code + message
- `GameSessionManager.submitMove()` now returns `MoveSubmissionResult` (accepted or rejected wrapper)
- New events: `RoomJoinedEvent`, `ChatMessageEvent`
- `PlayerContext` gained `VIEWING_RESULTS` state
- `Networking` abstract stub replaced by real `server/` and `client/` packages (see architecture diagram)
- `Database` remains in-memory but is seeded from JSON on startup via `UserRepository` + `CredentialsRepository`
- New `PlayerProfile` data model in `core/` with stats, MMR, friends, avatar
- `Leaderboard` gained `GameResult` and `PlayerRanking` supporting classes
- `PresenceService` tracks online status

' Notes
note right of GameSessionManager
  Move pipeline:
  1. Receive move from PlatformCore
  2. validateMove() → Validation
  3. applyMove() if valid
  4. evaluateEnd() after apply
  5. Return MoveSubmissionResult
  PlatformCore publishes event.
end note

note right of RoomManager
  Lobby lifecycle:
  - Creates rooms for game types
  - Tracks player occupancy
  - Signals readiness to start
end note

note right of MatchMaking
  Skill-based matchmaking:
  - Per-game queues with MMR range expansion
  - PlatformCore polls every 5 s via scheduler
  - Publishes MatchFoundEvent on match
end note

note right of NotificationService
  Routes alerts based on PlayerContext:
  - IN_GAME: update board, toggle input
  - DASHBOARD/IN_LOBBY: banner/badge
  - IN_QUEUE: queue status
  - VIEWING_RESULTS: post-game screen
end note
