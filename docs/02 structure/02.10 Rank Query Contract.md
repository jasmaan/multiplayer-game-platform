# G1.3 - Rank/MMR Query Contract
## Owner: Platform Core Sub-team
## Sub-Team: Platform Core
## Iteration: 1

---

# Purpose

This document defines the contract used by MatchMaking to query player skill data from Leaderboard for skill-based matchmaking.

The goal of this contract is to make the MatchMaking, Leaderboard interaction explicit by defining:
- how MatchMaking requests player rank/MMR data
- what data format is returned
- how fallback/error cases are represented
- how MatchMaking should use the returned data during queueing and match formation

---

# Design

- Keep the contract boundary explicit between MatchMaking and Leaderboard
- Support skill-based matchmaking using a numeric value suitable for comparisons
- Prefer MMR when available
- Keep MatchMaking and leaderboard independent
- Support both single player and group lookup for future matchmaking

---

# Components Involved

## Consumer
- MatchMaking

MatchMaking queries player skill data when:
- a player joins queue
- a matchmaking pass is run

## Provider
- Leaderboard

Leaderboard provides player skill data for a specific gameType, including:
- MMR
- a resolved numeric skill value for matchmaking use
- a fallback data if person is not placed yet

---

# Core Responsibilities

## MatchMaking Responsibilities
- Request skill data for queued players
- Use returned skillValue when comparing players for matchmaking
- Handle error statuses according to contract rules

## Leaderboard Responsibilities
- Accept skill queries from MatchMaking
- Retrieve player skill data for the requested gameType
- Resolve a usable skillValue
- Return status and error when full data is unavailable

---

# Contract Surface

The refined Platform Core diagram already defines the public Leaderboard methods used by this contract.

## Existing Leaderboard Methods

### getPlayerRank(playerId: String, gameType: String): int

Returns the player’s current rank value for the selected game type.

### getPlayerStats(playerId: String, gameType: String): Object

Returns the player’s stats object for the selected game type.

---

# MatchMaking Usage

MatchMaking uses Leaderboard data during skill-based matching as follows:

- getPlayerRank(playerId, gameType) is the main query when matchmaking needs player stats for comparison
- if a player is new or has no stats, MatchMaking uses a default value, as already described in the matchmaking design

This keeps the query contract aligned with the existing MatchMaking algorithm description.
